Claude Code is Anthropic's command-line AI assistant that helps you build and maintain documentation projects. With the Mintlify skill installed, Claude Code becomes a powerful documentation partner with deep knowledge of Mintlify's components, conventions, and best practices.

## Prerequisites

Before you begin, you'll need:

- An active **Claude subscription** (Pro, Max, or API access)
- **Node.js** version 16 or higher
- A Mintlify documentation project
- Terminal or command-line experience

## Installation and Setup

<Steps>
<Step title="Install Claude Code CLI">
  Install the Claude Code command-line tool globally using npm:

  ```bash
  npm install -g @anthropic-ai/claude-code
  ```

  Verify the installation:
  
  ```bash
  claude --version
  ```

  <Note>
  If you encounter permission errors, you may need to use `sudo` on macOS/Linux or run your terminal as administrator on Windows.
  </Note>
</Step>

<Step title="Authenticate with your Claude account">
  Run the authentication command:

  ```bash
  claude auth
  ```

  This will open your browser to log in with your Anthropic account. After successful authentication, return to your terminal.
</Step>

<Step title="Navigate to your documentation directory">
  Change to your documentation project root:

  ```bash
  cd /path/to/your/docs
  ```

  Verify you're in the correct location by checking for `mint.json`:
  
  ```bash
  ls mint.json
  ```
</Step>

<Step title="Install the Mintlify skill">
  Install the Mintlify skill to give Claude Code specialized documentation knowledge:

  ```bash
  npx skills add https://mintlify.com/docs
  ```

  This equips Claude Code with:
  - Complete Mintlify component library and usage patterns
  - MDX syntax and frontmatter requirements
  - Documentation structure and navigation best practices
  - Content writing guidelines and tone standards
</Step>

<Step title="Customize project instructions">
  Create an `AGENTS.md` file in your project root to define project-specific guidelines:

  ```markdown
  # Documentation Instructions

  ## Product Information
  - Product name: Acme Analytics Platform
  - Primary audience: Data engineers and analysts
  - Technical level: Intermediate to advanced

  ## Terminology Standards
  - "dataset" not "data set"
  - "API key" not "api key" or "API token"
  - "workspace" not "project" or "environment"

  ## Style Requirements
  - Use sentence case for all headings
  - Include at least one code example per page
  - Add descriptions to all frontmatter
  - Maximum heading depth: h3

  ## Content Boundaries
  - Document public APIs only
  - Exclude enterprise-only features
  - No pricing information in technical docs
  ```

  <Tip>
  Be specific in your `AGENTS.md` file. Claude Code will follow these guidelines when generating and editing documentation.
  </Tip>
</Step>

<Step title="Start Claude Code">
  Launch the interactive Claude Code session:

  ```bash
  claude
  ```

  You'll see the Claude Code prompt where you can start working on your documentation.
</Step>
</Steps>

## Using Claude Code for Documentation

### Interactive Documentation Workflows

<CodeGroup>
```bash Create New Pages
claude

> Create a new guide for API authentication at api/auth.mdx
> Include:
> - Frontmatter with title and description
> - Overview of auth methods (API key, OAuth, JWT)
> - Step-by-step setup for each method using <Steps>
> - Code examples in multiple languages using <CodeGroup>
> - Security best practices in a <Warning> callout
```

```bash Edit Existing Content
claude

> Review getting-started/quickstart.mdx
> Make these improvements:
> - Add prerequisites section
> - Expand installation steps with troubleshooting
> - Include a video embed
> - Add "Next Steps" card group at the end
```

```bash Batch Operations
claude

> Update all pages in api/ directory:
> - Add API version "v2" to all endpoints
> - Ensure all code blocks have language tags
> - Add rate limiting information where applicable
```
</CodeGroup>

### Code Example Generation

<Note>
Claude Code can generate realistic code examples in multiple languages. Always test generated code before publishing.
</Note>

<CodeGroup>
```bash Request Examples
> Add Python and JavaScript examples for:
> - Authenticating with API key
> - Making a GET request to /api/users
> - Handling rate limit errors
> - Parsing JSON response

> Format as <CodeGroup> with proper syntax highlighting
```

```python Example Output - Python
import requests

api_key = "your_api_key"
headers = {"Authorization": f"Bearer {api_key}"}

response = requests.get(
    "https://api.example.com/v1/users",
    headers=headers
)

if response.status_code == 429:
    retry_after = response.headers.get("Retry-After")
    print(f"Rate limited. Retry after {retry_after} seconds")
else:
    users = response.json()
    print(f"Retrieved {len(users)} users")
```

```javascript Example Output - JavaScript
const apiKey = "your_api_key";

const response = await fetch("https://api.example.com/v1/users", {
  headers: {
    Authorization: `Bearer ${apiKey}`,
  },
});

if (response.status === 429) {
  const retryAfter = response.headers.get("Retry-After");
  console.log(`Rate limited. Retry after ${retryAfter} seconds`);
} else {
  const users = await response.json();
  console.log(`Retrieved ${users.length} users`);
}
```
</CodeGroup>

## Best Practices

<AccordionGroup>
<Accordion title="Writing effective prompts for documentation">
**Good prompts are:**
- **Specific**: "Add TypeScript interfaces for the User and Team objects"
- **Structured**: "Include sections for: overview, prerequisites, setup, and examples"
- **Context-aware**: "Following our AGENTS.md terminology, document the workspace API"

**Avoid vague prompts:**
- ❌ "Make it better"
- ❌ "Add more information"
- ❌ "Update the docs"

**Use concrete prompts:**
- ✅ "Add error code reference table with descriptions and solutions"
- ✅ "Include curl examples for all POST endpoints"
- ✅ "Create troubleshooting section with 5 common issues"
</Accordion>

<Accordion title="Iterative refinement workflow">
1. **Start broad**: "Create an API reference page for the Users endpoint"
2. **Review output**: Check structure, completeness, accuracy
3. **Refine specifically**: "Add request parameter validation rules"
4. **Polish**: "Improve the introduction paragraph for clarity"
5. **Verify**: "Check all code examples for syntax errors"

This iterative approach produces better results than trying to get everything perfect in one prompt.
</Accordion>

<Accordion title="Version control integration">
Claude Code works well with Git workflows:

```bash
# Create a feature branch for documentation updates
git checkout -b docs/api-v2-updates

# Use Claude Code to make changes
claude "Update all API endpoints to v2 format"

# Review changes
git diff

# Commit with descriptive message
git add .
git commit -m "docs: update API endpoints to v2 format"

# Push and create PR
git push origin docs/api-v2-updates
```
</Accordion>
</AccordionGroup>

## Troubleshooting

<AccordionGroup>
<Accordion title="Authentication errors">
If Claude Code fails to authenticate:

```bash
# Clear existing credentials
claude auth logout

# Re-authenticate
claude auth

# Verify authentication status
claude auth status
```

If problems persist, check your Claude subscription status at [console.anthropic.com](https://console.anthropic.com).
</Accordion>

<Accordion title="Skill not being utilized">
Ensure the Mintlify skill is properly installed:

```bash
# Check installed skills
npx skills list

# Reinstall if missing
npx skills add https://mintlify.com/docs --force

# Verify in project root
ls -la .skills/
```

<Tip>
Start your prompts with "Using Mintlify components..." to explicitly activate skill knowledge.
</Tip>
</Accordion>

<Accordion title="Generated content doesn't match project style">
This usually means your `AGENTS.md` file needs more detail:

1. Add specific examples of approved writing style
2. Include terminology do's and don'ts
3. Provide sample page structures
4. Reference existing high-quality pages as templates

Example addition:
```markdown
## Style Examples

### Good: Active Voice
"Configure your API key in the dashboard"

### Bad: Passive Voice
"The API key should be configured in the dashboard"
```
</Accordion>

<Accordion title="Performance or timeout issues">
For large documentation projects:

```bash
# Work on specific directories
cd api/
claude "Update all endpoint documentation"

# Use targeted prompts instead of "entire project"
claude "Update files in guides/ directory only"

# Break large tasks into smaller chunks
claude "Update authentication docs" # First task
claude "Update authorization docs"  # Second task
```
</Accordion>
</AccordionGroup>
