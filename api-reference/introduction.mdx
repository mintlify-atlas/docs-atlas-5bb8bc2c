## Authentication

All API endpoints are authenticated using Bearer tokens and picked up from the specification file.

```json
"security": [
  {
    "bearerAuth": []
  }
]
```

### Getting Your API Key

<Steps>
  <Step title="Sign in to your account">
    Navigate to your dashboard and access the API settings page.
  </Step>
  <Step title="Generate a new token">
    Click **Create API Key** and give it a descriptive name.
  </Step>
  <Step title="Store securely">
    Copy your API key immediately - you won't be able to see it again.
  </Step>
</Steps>

<Warning>
  Never share your API key or commit it to version control. Always use environment variables to store sensitive credentials.
</Warning>

### Making Authenticated Requests

Include your Bearer token in the Authorization header of every request:

<CodeGroup>

```bash cURL
curl -X GET "http://sandbox.mintlify.com/plants" \
  -H "Authorization: Bearer YOUR_API_KEY"
```

```javascript JavaScript
const response = await fetch('http://sandbox.mintlify.com/plants', {
  headers: {
    'Authorization': 'Bearer YOUR_API_KEY'
  }
});
```

```python Python
import requests

headers = {
    'Authorization': 'Bearer YOUR_API_KEY'
}
response = requests.get('http://sandbox.mintlify.com/plants', headers=headers)
```

</CodeGroup>

## Rate Limiting

The API implements rate limiting to ensure fair usage:

- **Rate limit**: 100 requests per minute per API key
- **Burst limit**: 20 requests per second

When you exceed the rate limit, you'll receive a `429 Too Many Requests` response.

<Expandable title="Rate Limit Headers">
  Each API response includes headers that help you track your rate limit status:

  - `X-RateLimit-Limit`: Maximum number of requests per minute
  - `X-RateLimit-Remaining`: Number of requests remaining in the current window
  - `X-RateLimit-Reset`: Unix timestamp when the rate limit resets
</Expandable>

## Error Handling

The API uses standard HTTP response codes to indicate success or failure:

| Status Code | Description |
|------------|-------------|
| `200` | Successful request |
| `204` | Successful request with no content |
| `400` | Bad request - check your parameters |
| `401` | Unauthorized - check your API key |
| `404` | Resource not found |
| `429` | Too many requests - you've hit the rate limit |
| `500` | Server error - try again later |

All error responses include a JSON body with details:

```json
{
  "error": 400,
  "message": "Invalid parameter: limit must be a positive integer"
}
```
